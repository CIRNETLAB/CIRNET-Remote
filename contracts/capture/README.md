# NCAP capture formats

`layout.json` is the checked binary layout authority. The unified contract generator emits the browser constants and `contracts.boundary.capture_layout`; Python also has a resource-backed accessor so fresh generation does not depend on already generated modules. `ncap.schema.json` defines the closed sampled descriptor contracts under the versioned `https://netcircuit.local/contracts/capture/ncap/2.0/schema.json` identity. Historical CaptureMetadata 1.0 remains unchanged.

Both versions start with the same 9-byte prefix: ASCII `NCAP`, one unsigned version byte, and a little-endian unsigned 32-bit JSON-header byte length. UTF-8 JSON follows, then the exact binary body. Headers must be nonempty and at most 65,536 bytes. Invalid UTF-8, a BOM, duplicate members (including equal values), extra fields and trailing body bytes are rejected. Header integer fields use plain decimal integer tokens; fractions and exponents cannot disguise integer counts. Binary v2 calibration numbers must survive decimal-to-binary64-to-decimal conversion without losing their written digits. Integer tokens outside the JavaScript safe integer range are rejected, including calibration integer tokens; scientific notation is available for representable large floating-point calibration values.

## Version 1: digital events

The header contains exactly `encoding: "digital_events"`, the ordered `signals` table, `sample_count` and `duration_ns`. Each 11-byte little-endian `<HQB` record contains an unsigned 16-bit channel-table index, unsigned 64-bit nanoseconds and one value byte (`0`, `1`, or `2` for unknown `X`). The event order remains unchanged, including equal or nonmonotonic timestamps. Values and timestamps are never resampled. Timestamps cannot exceed the declared duration or 9,007,199,254,740,991; the channel table has at most 4,096 unique nonempty names and the payload at most 100,000 events. The existing encoder still sorts the channel table and emits exactly the committed legacy golden bytes.

The existing runtime endpoint, MIME version and CaptureStore continue to produce and validate v1 only. SHA-256 is external CaptureMetadata evidence over the entire prefix, JSON header and body; the binary v1 header gains no new checksum field.

## Version 2: frame-interleaved sampled data

`AnalogCaptureDescriptor` 2.0 contains the complete expected header, exact `payload_byte_count`, and lowercase `sha256` of the complete binary payload. The binary header is an `AnalogCaptureHeader`; its values must match the descriptor, independent of JSON object member order. Capture identity and generation therefore participate in the hash and agreement check. SHA stays outside the binary header to avoid a circular digest.

The encoding is uniformly `INT16`, `UINT16`, or IEEE-754 `FLOAT32` for the whole capture, always little-endian. The body stores frame 0 / channel 0, frame 0 / channel 1, then frame 1 / channel 0, and so on, using the declared channel order. `frame_count` counts stored frames, not individual scalar values. The format policy permits at most 100,000 frames and eight channels; these are parser resource bounds and make no claim about station capabilities. The body size must equal `frame_count * channels.length * bytes_per_value` exactly. Nonfinite FLOAT32 values and nonfinite calibrated results reject the artifact; invalid-quality annotations do not sanitize malformed bytes.

Each channel declares its ID, unit, nonzero scale, offset, increasing physical range and nullable calibration ID. Physical values are `raw * scale + offset`. An absent calibration ID does not invent traceability. Values outside the declared range are retained and explicitly labelled as clipping; no clamping is performed. The declared clipped-channel list refers only to known channels.

The time axis explicitly declares `capture_relative`, `unix_epoch`, or `device_clock`. Capture-relative coordinates require a zero anchor. Device-clock coordinates require an opaque clock ID and cannot be labelled UTC; the other references require a null clock ID. The axis uses a decimal-string nanosecond anchor and a positive rational sample rate `numerator / denominator` Hz. Exact frame time is exposed as a bigint/integer rational, without converting the anchor to a floating-point timestamp. A gap at stored index `i` represents missing frames before frame `i`; index zero represents leading loss, and index `frame_count` trailing loss. Gap positions are strictly increasing. Frame `i` is at `anchor + (i + sum(gaps at or before i)) * 1e9 * rate.denominator / rate.numerator`. Trailing loss remains quality evidence even though it has no stored sample.

Quality declares status, termination reason, exact lost-frame count, gaps, sorted disjoint invalid stored ranges and clipped channel IDs. Gaps must account for every lost frame. `VALID` requires complete termination with no loss or invalid ranges. `PARTIAL` requires incomplete termination or invalid ranges, with no transport loss. `LOSS` requires recorded loss. `INVALID` retains evidence while withholding trusted amplitude display. Termination values include complete, stopped, duration/buffer limits, transport loss, driver error and unknown; they never imply successful hardware application.

## Decoder, transport and display boundaries

Python `decode_sampled` verifies descriptor shape, shared relationships, SHA, header agreement and exact body layout before returning owned raw values. The browser's pure `decodeAnalogCapture` performs structural decoding and reports `integrity: "unchecked"`. `verifyAndDecodeAnalogCapture` verifies SHA before returning `integrity: "verified"`. A missing integrity primitive fails explicitly. Cancellation after a late body or hash completion cannot publish a capture.

`loadAnalogCapture` requires an explicit `AnalogPayloadSource`. The source receives capture identity, cancellation and an exact byte bound and must enforce owner access and an appropriate versioned transport. There is deliberately no default v2 network source: the runtime still exposes v1 and default Scope channels remain zero. A future producer needs an explicit station profile and versioned endpoint before this loader can be connected to runtime Scope data. No sampled hardware producer is implemented here.

The pure `createDisplayEnvelope` helper produces at most 4,096 min/max buckets for an explicitly selected frame range and channel. It retains every valid extremum in each bucket and keeps raw typed arrays intact. The result identifies itself as a display envelope and carries source, synthetic/measured provenance, integrity, quality, units, discontinuity, invalidity and clipping. Invalid ranges are excluded from amplitudes; wholly INVALID captures have null amplitudes. Exact rational times remain available alongside approximate relative offsets for plotting. The display helper does not smooth, interpolate, reconnect across gaps, grade results or replace raw evidence.

## Shared fixtures

`contracts/fixtures/capture/conformance.json` contains committed, independently packed synthetic golden bytes consumed by Python and browser tests. It covers legacy byte preservation, UTF-8 names, exact timestamps and unknown levels; all three sampled encodings; calibration including negative scale; rate and anchor precision; empty, partial, invalid and lost captures; clipping; malformed headers, body sizes and checksums. Annotated semantic cases also compare structured issue code, path, severity and profile. These fixtures demonstrate format interoperability, not physical measurement or hardware operation.
