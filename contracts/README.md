# Canonical contracts and generated boundaries

JSON Schemas own shapes, FastAPI registrations own public operations, and protobuf owns local RPC fields. The machine-readable [manifest](manifest.json) records identity, version, visibility, producer/consumers, profiles, artifacts and compatibility policy. Absolute URIs resolve from packaged resources without network access or the current directory. Historical relative schema IDs remain readable through the manifest registry.

The generation CI uses Python 3.12 and Node 22; runtime contracts support Python 3.11+. The installed-package CI also tests Python 3.11. From the repository root, install the shared verification pins and four local packages, then the browser generator tools:

```sh
python -m pip install -r requirements-verification.txt -e . -e './services/api[test]' -e './simulator/circuit-simulator[test]' -e './services/hardware-service[dev]'
cd apps/web && npm ci --no-audit --no-fund
```

Return to the repository root for these commands. The API and simulator are needed to export registered operations without starting runtime services:

```sh
python scripts/generate_contracts.py
python scripts/generate_hardware_rpc.py
python scripts/generate_contracts.py --check
python scripts/check_contract_package.py
python scripts/check_release.py --group contracts
```

`sync_lab_contracts.py [--check]` remains a compatibility entrypoint for unified generation. Make targets `contracts-generate` and `contracts-check` invoke the same commands. Check mode generates into a temporary tree and never repairs drift. UTF-8/LF, stable manifest order, no timestamps, pinned tools and Python AST normalization define deterministic output. Every generator must finish before outputs are published. All candidates are prepared before atomic per-file replacements, and an ordinary publication I/O failure rolls back prior replacements (tested by fault injection). Process termination or power loss is not a filesystem-wide transaction; rerun check/generate after interruption.

Generated Python models live in `contracts/boundary`; generated browser DTOs and standalone Ajv 2020 validators live in `apps/web/src/contracts/generated`. Existing `src/types` files are compatibility facades. Browser exports exclude private `InstrumentationExecutionPlan` and `StationCapabilities`; the public capability projection omits routing resources. Public configuration vocabulary is generated independently. FastAPI registrations generate `contracts/api/openapi.json` and browser operation bindings in the same staged generation run. Open object properties/metadata are intentional opaque extension points, not missing core DTO schemas.

The structural, editor and transport profiles are versioned separately in [profiles.json](profiles.json). Structural storage preserves arbitrary precision legacy graph numbers. Browser import examines original numeric tokens before conversion and rejects precision loss; normalization of legacy property aliases is a separate document operation. Transport intersects JS-safe integer bounds and protobuf uint32 limits before RPC serialization. Epoch `timestamp_ns` remains a decimal string. No value is clamped or truncated.

Pydantic/TypeScript represent shapes; the full offline JSON Schema validator enforces composition, external references and conditionals. Array bounds, string patterns, numeric bounds, mounting `if/not` rules and cross-field relationships are runtime constraints, even when generated TypeScript cannot express them. Generation rejects unknown vocabulary and unresolved/private references instead of silently widening them. Python boundary adapters preserve numeric input representations and omission; route serialization must use `response_model_exclude_unset=True`.

Shared rule IDs and examples live in `fixtures/conformance.json`; Python and browser run the same public cases. Explicit internal-only cases also run in Python. Editor authoring, server execution, physical evidence and electrical safety remain distinct contexts. Generic contract approval cannot create a safety permit, prove a physical path or enable an unavailable instrument.

`compatibility/2026-10-16` freezes exact Git blobs for supported unpublished pre-W1 schemas/RPC and records the source revision. Its `public-wire-baseline.json` additionally freezes the current supported unpublished API operation/request/response/security anchors, named schemas and NCAP layouts. `python scripts/check_public_compatibility.py` rejects changes to those anchors; new operations and versioned definitions can coexist with them. Tests include negative mutations. There is no automatic baseline replacement command. Raw Windows-checkout digests are also recorded; comparisons normalize CRLF to LF only. It is not a released-version claim. Existing graph 1.0/1.1 schemas are unchanged. LF attributes preserve baseline and generated artifact bytes across clean Windows/Linux checkouts. New presentation namespaces are opt-in and preserve unknown/future metadata. Breaking public shapes require a new version and tested migration. Named boolean root DTOs and dynamic-reference relocation are currently explicit generation errors; nested boolean schemas and full 2020-12 runtime constraints are supported. These unsupported generation cases never become permissive DTOs.

The wheel includes schema/data/baseline/fixture/proto resources and generates RPC bindings at build time. Core runtime needs pinned JSON Schema/referencing/Pydantic dependencies; install `[rpc]` for generated local RPC imports. API and hardware pin the same grpcio/protobuf versions as the generator; FastAPI/Pydantic versions are pinned for deterministic operation export. `requirements-verification.txt` also includes the optional workload monitor dependency because its owned-process cleanup regression runs in integration verification.

`check_contract_package.py` stages clean source without ignored RPC bindings or cached build trees, builds all four wheels, and installs them into a fresh venv. Its `-I` probe, venv and working directory are physically outside the checkout, and every imported package path is checked. It tests packaged schema/fixture/proto/layout resources, graph 1.1 preservation, NCAP v1/v2, domain dispatch, RPC limits, migrations through 0005, authentication/project/capture persistence and installed migration/bootstrap/retention CLIs. By default it uses OS temporary storage. If that directory is restricted, pass `--temporary-root /absolute/writable/external/directory`; checkout descendants are rejected and only the owned temporary child is cleaned up. Build logs use the shared external `package-check` artifact directory. `scripts/artifact_paths.py` delegates path validation to `scripts/artifact-paths.mjs`; see [verification storage](../docs/VERIFICATION.md) for session configuration and cleanup.

`python scripts/check_release.py --show-plan` lists the release commands. The contracts group checks repository context and generates ignored RPC bindings before checking committed DTO artifacts and running tests; the standalone Python group also bootstraps those bindings. Editable installation builds RPC bindings through the package build hook, and this explicit step makes verification independent of an earlier build cache. The default `--group all` runs contracts, the full Python suite once, browser unit/build/boundary checks, actual PostgreSQL migrations/races, real browser scenarios and installed packages. `--group` can be repeated to select a subset. The PostgreSQL group requires `NETCIRCUIT_TEST_POSTGRES_URL` pointing at a disposable test database; it fails clearly when absent. Tests create and clean only their own random schemas. Matching PostgreSQL 18 client tools must be on PATH or selected with `NETCIRCUIT_TEST_PG_BIN`. Browser checks require installed Chromium. Forward external package scratch with `--package-temporary-root`. Make targets `contracts-suite`, `python-check`, `web-check`, `postgres-check`, `browser-check`, `package-check` and `release-check` invoke this runner; override `PYTHON` when needed.

The load measurement is explicit: `python scripts/check_release.py --group load` runs 50 cookie/CSRF sessions, concurrency 10, eight actual virtual captures and three read rounds. Raw JSON uses the shared external `web-sessions/report.json` artifact location; a direct `scripts/benchmark_web_sessions.py --output` override must name a validated absolute external file. Retain the reviewed scenario/environment/results in an existing Markdown verification report, then clean only the owned external session. The load group is excluded from the default group and ordinary PR gates. Authentication pacing remains enforced. This bounded local workload does not establish target hardware or production deployment capacity; the dated 2026-10-16 reports preserve their original measurements.
