# Web/Contracts decisions — 2026-10-16

Authority remains `docs/ARCHITECTURE.md`, Lab-First v3.1. These decisions implement the supplied W0–W8 task; they do not revise electrical safety or hardware readiness.

## D01 — Shape authority and generation

JSON Schema 2020-12 owns data shapes. The manifest gives historical schemas stable absolute identities without changing their bytes; Python referencing and generated Ajv validators resolve offline. Pinned datamodel-code-generator and json-schema-to-typescript own Python/TS shape generation. Runtime validation retains constraints the type systems cannot express. FastAPI registrations will own operations/OpenAPI; protobuf remains the local wire authority. Browser output excludes the private execution plan. Cost if wrong: rebuild all generated consumers together and migrate public shapes explicitly.

## D02 — Validation contexts and numeric compatibility

Keep historical graph 1.0/1.1 structural acceptance, including arbitrary precision Python integers in editor fields. Browser file import checks original number tokens and rejects precision loss rather than rounding. Three separate structural/editor/transport validators share canonical shapes and explicit profile overlays. Transport adds JS-safe integer envelopes and protobuf uint32 restrictions before serialization; timestamp_ns stays a decimal string. No clamp/truncation is allowed.

JSON Schema treats mathematically integral `1.0` as an integer. Generated Python boundaries preserve this representation rather than coercing it to `1`; strict schema validation precedes generated model parsing. The API compatibility facade retains its pre-existing stricter integer representation rule for mount/contact `version`. This is an explicit application profile, not a change to legacy JSON Schema semantics. Numeric schema_version is invalid because supported versions are strings.

Generic cross-field invariants (state/history, capture count/duration/availability/encoding, identity/reference uniqueness, endpoint binding exclusivity and memory depth) have shared rule IDs and fixtures. Editor import still adds authoring/renderability rules; physical design/evidence and safety/permission remain separate server contexts. Cost if wrong: a stored legacy document may remain structurally readable while editing/execution reports a precise unsupported field; it must never silently change meaning.

Scheduled event budget and capture payload sample budget remain distinct (1M versus 100k in existing contracts). W7 verifies the existing executor policy: a high scheduling budget can complete a small genuine capture, while the 100,001st observation raises CAPTURE_LIMIT without returning a truncated success. The current Hardware Service maps simulation errors to UNEXECUTABLE. Neither limit is silently clamped and the historical contract shapes remain unchanged.

## D03 — Compatibility and packaging

Freeze exact supported Git schema/RPC blobs at `contracts/compatibility/2026-10-16`, with source revision, raw Windows checkout digests and an explicit CRLF→LF-only comparison rule. LF attributes preserve generated/baseline bytes across clean Windows/Linux checkouts. This is a support baseline, not a fabricated release. New visual/lead namespace contracts are opt-in; existing open metadata and unknown/future visual versions remain preserved. Generate/check stages all outputs first; check never repairs drift. Ordinary publication I/O failures restore previously replaced outputs; interrupted processes/power loss require check/regeneration. Wheel builds include resources and generate RPC from proto. Cost if wrong: reject the package gate and regenerate/rebuild, rather than depending on an editable checkout.

## D04 — Proposal mapping and pending later-phase decisions

The superseded Web proposal's `PhysicalExecutionPlan` maps to current `InstrumentationExecutionPlan`. `FpgaExecutionImage` remains hardware-internal proposal material. The FPGA proposal revision 2.1 is not a frozen ABI and closes no hardware gates. Keep HTTP NCAP v1, observed-node infrastructure routing, separate execution/capture lifetimes and honest zero instrument capabilities.

Instrument approved paths versus arbitrary analog routing (W2), durable principal/session/control-client separation and guest claims (W3), document CAS revisions (W4), and bounded realtime resync (W2/W6) require their own verified implementation decisions before being marked complete. The historical R/H exclusions describe that earlier scope; they do not exclude work explicitly requested in W3/W7. No implementation is claimed by recording this decision.

## D05 — Public operations, recovery and capabilities

FastAPI registrations own operation paths, methods, status codes and parameter locations. Canonical schemas own DTO shapes; the schema-only application exports OpenAPI and typed browser operation bindings during staged generation. Importing the application or exporting schemas cannot create a database, run restart recovery or connect to hardware. Normal runtime initialization remains in the application lifetime.

Public station capabilities omit routing resources. The unchanged internal StationCapabilities and execution plan remain Python/RPC-only. Internal corpus cases are explicitly tagged; equivalent public capability cases preserve browser semantic coverage. A station descriptor must agree with its nested capability identity/mode.

Create stores its experiment and operation identity in one transaction. Run/Stop identity is scoped to principal, kind and experiment; a per-key lock prevents same-key concurrent side effects without blocking unrelated Stop behind slow Create. A new Run key must pass lifecycle validation. Recovery of an existing REQUESTED Run may recognize persisted admission, but never replay Start. Run APPLIED means Start acknowledged, evidenced by persisted CAPTURING history; a later capture fault remains the experiment result. Stop APPLIED means terminal and actual safe lease release, with no quarantined lease. Successful operations have no operation error; historical experiment errors remain visible independently. These boundaries are independent of polling timing.

Realtime uses protocol 1.0, a fresh stream identity, monotonic per-subscription sequence and aggregate revisions. Bounded queue overflow sends explicit resync.required before the next snapshot. Hello always requests authorized snapshot reconciliation. No command replay is supported. Session authorization/control context and complete application recovery remain W3/W6 gates.

Approved instrument paths are validated by instrument role, endpoint, channel and current profile resources. Arbitrary analog circuit routing is a separate capability. The existing internal profile/RPC already expresses the approved path, so no hardware ABI change is needed. The physical default still has zero Scope/Generator channels and unavailable execution without validated driver support. See the instrument-path decision and compiler/native/loopback RPC evidence.

## D06 — Identity, authorization and disclosure

Durable principals, revocable server sessions and volatile per-tab control contexts have distinct lifetimes. Existing guest ownership remains isolated and only transfers after proven possession and explicit claim; stale/repeated rotations cannot reuse that proof. Unknown environment configuration fails closed, and disabling guests also invalidates previously persisted guest authority. Rejected unsafe origins cannot set a replacement cookie. Expired/revoked supplied cookies signal 401 instead of silently presenting guest state to an authenticated UI.

Role checks do not grant another user's private data. Assignment disclosure is an explicit stored policy: observed_only exposes status and observations; detailed reference/answer diagnostics require author/Admin access or an explicitly detailed publication. One manager public projection covers HTTP, operation recovery and realtime. Complete evidence and verification/safety algorithms remain unchanged. Historical migration schemas are frozen independently from mutable current SQLAlchemy metadata. PostgreSQL DDL compilation is not live database verification; production rollout requires the documented backup/rehearsal gate.

## D07 — Document revisions and admission authority

A server document ID is independent of the embedded graph ID. Save As copies the canonical document without silently retagging graph identity. Storage preserves structural graph 1.0/1.1 values; editor representability and execution remain separate boundaries. Saves and deletion use a database compare-and-swap revision, immutable saved revisions, owner scope and parent liveness. A matching save ACK acknowledges only the submitted local revision; later edits remain dirty. Export does not acknowledge a server save. Local recovery is bounded and partitions every draft by durable principal, including unbound imported JSON.

Create pins a saved graph revision or an inline graph together with configuration and assignment context. Editing the server document or assignment later cannot rewrite an admitted experiment. A physical assignment context is not observed topology. Legacy CREATED/QUEUED records pin at first admission/recovery with provenance; missing legacy context blocks Start explicitly.

Session authorization must be linearized with the actual write. Independent-repository reproductions proved that a process-local mutex and an earlier SELECT can permit an orphan guest write after claim. A conditional no-op session UPDATE acquires the SQLite writer lock or PostgreSQL session row lock, then resolves current authority in that same transaction. It neither extends the session nor changes its auth revision. Project mutations and experiment creation use this fence; the latter inserts experiment, immutable document reference and Create identity atomically. The saved-document insert also checks live ownership at the write. Claims/revocation either happen first and reject the stale mutation, or follow the committed write and include it in transfer.

## D08 — Requested instruments, signal domains and sealed evidence

The unchanged InstrumentCapabilities remains the only channel-count authority. A separate, owner/session/tab/lease-bound InstrumentControlAccess describes usable-now allocation without copying hardware routes or adding another count. Generator commands commit a unique durable identity before invoking the existing approved adapter. ACCEPTED is distinct from APPLIED; only an explicit `hardware_applied=true` acknowledges application. A timeout or lost acknowledgement remains REQUESTED/ACKNOWLEDGEMENT_UNKNOWN. Reading or retrying the original identity never replays output. Legacy instrument response shapes remain supported. Unsupported trigger drafts and hardware clock paths cannot be silently serialized away.

Signal domains live in the component catalog and an opt-in, versioned module `signal_domains` namespace, preserving frozen graph 1.0/1.1 shapes. Future namespace versions remain readable in storage but cannot execute without an adapter. An annotation cannot relabel a known catalog port or grant an unknown component an execution model. CLOCK/DIGITAL compatibility and the existing bounded DC adapter are explicit; MIXED is not a wildcard. Typed SPICE/mixed adapters report unavailable without a capture. Existing digital/DC simulation is still the only implemented executor; the virtual station now admits supported graph 1.1 through that same compiler rather than rejecting it with a stale 1.0 guard.

NCAP v1 bytes and its runtime endpoint remain supported. NCAP v2 adds a separately versioned sampled descriptor and binary codec for INT16/UINT16/FLOAT32. Exact rational time, explicit clock reference, channel calibration, clipping, loss, invalidity, generation and termination are evidence, not promises of acquisition. Synthetic shared fixtures exercise interoperability. No default v2 runtime payload source or analog producer is installed. Display envelopes preserve raw measurements and cannot grade timing or bridge missing samples.

Migration 0005 indexes sealed capture identities independently of the current experiment generation. Ownership is derived from the experiment, including guest claims. Retirement commits unavailable metadata and an audit entry before filesystem cleanup; failed deletion remains pending and is retryable. Parent-row fences serialize retirement with claims and new reservations. Per-capture I/O guards never hold the manager control lock or a database transaction while reading, hashing or deleting bytes. Authorization is checked again after a read. Quotas bound capture files and bytes for the supported single API-writer process; retention is an explicit bounded maintenance command, not work inside the safety/lease monitor. Setting retention to zero disables expiration while allowing pending cleanup to retry.

## D09 — Credential rotation and old transport replies

Final native-browser release verification exposed an old guest WebSocket closing4401 while login had committed but its response was still pending. Invalidating that old connection aborted adoption of the new session. Deterministic frontend coverage exercises the real Vue connection composable/EventClient and a pending auth request; failed or lost rotations must reconcile identity once through a bounded read-only session request, without replaying the mutation or retaining revoked control authority.

Independent raw HTTP regressions also proved that an old revoked-cookie or no-cookie read can arrive after login and install a different guest cookie. A JavaScript response-version guard cannot prevent the browser applying Set-Cookie. Credential installation therefore belongs only to explicit `GET /api/auth/session` bootstrap and successful auth mutations. Ordinary expired/unauthenticated reads still return their existing401/code but do not set replacement credentials. Clients bootstrap explicitly after invalidation. Durable ownership, cookie flags, CSRF/origin checks and public DTO/version shapes remain unchanged; no database migration or silent reauthentication is introduced.

Legacy migration preserves a valid old cookie's owned read access and one-time claim proof. Ordinary reads create real internal revocable contexts bounded by the old proof's expiry but neither consume that proof nor install a credential. Explicit bootstrap consumes it once and installs the opaque cookie/CSRF. This deliberately replaces automatic installation on an ordinary legacy GET; its previous regression was expanded to assert proof retention, actual pre-bootstrap capture access and the same later login/claim/operation isolation. Held old response→bootstrap/login/claim cannot overwrite the new cookie; held binary read→claim cannot disclose bytes after revocation. See `test_auth_migration_integration.py`, `test_auth_cookie_loss.py` and `test_auth_service.py`. Exempting legacy reads from the no-cookie rule would reintroduce the delayed-response race and is rejected.
